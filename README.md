# 实验：题库类组合三角形题目类（简单几何图形题库系统）

## 一、文件说明（多文件方式组织代码）

| 文件 | 作用 |
| --- | --- |
| `Triangle.h` | 【部分类】Triangle 的**类声明**（数据成员 + 成员函数原型） |
| `Triangle.cpp` | 【部分类】Triangle 的**成员函数定义** |
| `QuestionBank.h` | 【整体类】QuestionBank 的**类声明** |
| `QuestionBank.cpp` | 【整体类】QuestionBank 的**成员函数定义** |
| `main.cpp` | 生成对象、调用成员函数的主函数 |

类的声明、定义、对象生成分别放在不同的文件中，符合"多文件方式组织代码"的实验要求。

## 二、类之间的关系：组合关系（整体 — 部分）

```
        QuestionBank（整体类 / 题库类）
   ┌─────────────────────────────────────┐
   │ - bankName : char[30]               │
   │ - count    : int                    │     组合关系
   │ - questions[50] : Triangle          │◆──────────────┐
   │ - scores[50]    : int               │               │  题库对象内部直接
   │ - average       : double            │               │  包含题目对象数组
   └─────────────────────────────────────┘               │  生命周期一致：题库撤销
                                                          │  → 题目对象一起撤销
                                                          ▼
                              Triangle（部分类 / 三角形题目类）
                    ┌──────────────────────────────────────┐
                    │ - id          : int      题目编号      │
                    │ - sideA/B/C   : double   三条边长      │
                    │ - userAnswer  : char[24] 用户答案      │
                    │ - rightAnswer : char[24] 正确答案      │
                    └──────────────────────────────────────┘
```

组合关系在设计上的体现：

1. `QuestionBank` 的数据成员中有 `Triangle questions[MAX_NUM];` —— 整体类**直接包含**部分类对象数组；
2. 题库对象撤销时，里面的题目对象也**自动一起撤销**（析构函数的输出可以观察到这一点）；
3. 部分类对象不能脱离整体类长期存在，整体与部分的生命周期一致。

## 三、功能实现对照

**Triangle（部分类）**

- 数据成员：题目编号、三条边长、用户答案、正确答案，全部 `private`，通过公有成员函数访问；
- 合法性验证：`isValid()` 判断两边之和是否大于第三边，非法三边拒绝写入；
- 初始化 / 修改：`init()`、`setSides()`、`setUserAnswer()`；
- 获取：`getId()`、`getSideA/B/C()`、`getUserAnswer()`、`getRightAnswer()`；
- 输出：`show()`；
- 其他功能：`perimeter()` 周长、`area()` 面积（海伦公式）、`calcRightAnswer()` 判断三角形类型（等边 / 直角 / 等腰 / 一般）、`checkAnswer()` 判分；
- 默认构造函数：编号 0、三边 0、答案为"未作答 / 非三角形"；
- 重载构造函数：`Triangle(int newId, double a, double b, double c)`；
- 析构函数：只对真正的题目对象（编号 > 0）输出提示。

**QuestionBank（整体类）**

- 数据成员：题库名称、题目数量、包含的所有题目、所做题目的成绩、平均分；
- 默认构造函数 / 重载构造函数 `QuestionBank(const char *name)` / 析构函数；
- 增加题目 `addQuestion()`：题库满或题目非法时拒绝入库；
- 删除题目 `deleteQuestion()`：按编号查找，后面题目整体前移，空位清空；
- 查询题目 `queryQuestion()`：按编号显示题目、答案与得分；
- 做题判分 `answerQuestion()`：记录用户答案、自动判分（每题 10 分）、刷新平均分；
- 计算平均分 `calcAverage()`、输出显示 `show()`。

## 四、编译运行

方式一：命令行（g++）

```bash
g++ -Wall -o bank.exe Triangle.cpp QuestionBank.cpp main.cpp
./bank.exe
```

方式二：Dev-C++ / CodeBlocks 等多文件工程

1. 新建工程（Console Application，C++），把 5 个文件加入同一个工程；
2. 编译运行即可，**不要单独编译某一个 .cpp**，多文件必须一起编译链接。

方式三：Visual Studio（2015 / 2017 / 2019 / 2022 / 2026 通用）

1. **新建 → 项目 → 空项目**（Visual C++ / 空项目）。
   不要选"控制台应用"模板：它会自带一个含 `main()` 的源文件和预编译头，容易出现 `LNK2005`（main 重复定义）或 `C1010`（找不到预编译头）。
2. 右键项目 → **添加 → 现有项**，把 5 个文件全部加进去（`.h` 加到"头文件"筛选器、`.cpp` 加到"源文件"筛选器，位置不影响编译）。
3. **生成 → 生成解决方案**，再 **调试 → 开始执行（不调试）**（Ctrl + F5，这样运行完窗口会停住）。

VS 上的三个常见问题（均已在本工程中处理并实测验证）：

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| **编译报几十上百个错**：`warning C4819 该文件包含不能在当前代码页(936)中表示的字符`，跟着大量 `error C2001 字符串字面量中的换行符`、`error C2146 语法错误: 缺少")"` | 源文件是 **UTF-8 无 BOM**，MSVC 不知道它是 UTF-8，就按本机代码页 GBK 逐字节解析；中文的字节被两两配对后错位，把字符串的收尾引号一并吞掉，编译器于是认为"字符串没结束、括号没配对" | ① 源文件保存为 **UTF-8 带 BOM**（本工程 5 个源文件已如此）；② 或 项目属性 → C/C++ → 命令行 → 其他选项 里填 `/source-charset:utf-8`。本工程两种都做了，互为保险 |
| `error C4996: 'strcpy': This function or variable may be unsafe` | VS 新建工程默认开启"SDL 检查"，它会把这条废弃函数警告**提升为错误** | 已在 3 个 `.cpp` 文件首行加入 `#define _CRT_SECURE_NO_WARNINGS`（也可在 项目属性 → C/C++ → 预处理器 → 预处理器定义 里添加同名宏，或把 SDL 检查设为"否"） |
| `fatal error C1010: 在查找预编译头时遇到意外的文件结尾` | 工程启用了预编译头 | 用"空项目"建工程；或 项目属性 → C/C++ → 预编译头 → 选择"不使用预编译头" |

两点提醒（实测结论）：

- 在 VS 里打开源文件后，不要用"另存为"把编码改成 "UTF-8 无 BOM"，那会把 BOM 去掉、上述几十个错误立刻回来。
- **不要用 `/utf-8` 代替 `/source-charset:utf-8`**。实测两者都能让编译通过，但 `/utf-8` 会把字符串也按 UTF-8 存进可执行文件，中文控制台（代码页 936）显示出来就是乱码；用 `/source-charset:utf-8` 时输出仍是 GBK，中文正常。

本工程代码为标准 C++98 语法（`char` 数组 + 定长数组 + `strcpy/strcmp` + `cmath`），不含 STL、模板、GNU 扩展，MSVC 与 g++ 均可编译。
（已在本机用 **MSVC 19.51 / VS 2026** 与 **g++ 8.1 / MinGW** 双编译器实测，均零错误零警告通过，运行输出逐行一致。）

> 提示：Dev-C++ 同样是"新建工程 → 加入全部 5 个文件 → 编译运行"，不要单独编译某一个 `.cpp`。

## 五、运行结果要点

- 非法三边 1、2、10 被合法性验证拦截，修改无效、不能入库；
- 3、4、5 → 直角三角形；6、6、6 → 等边三角形；5、5、8 → 等腰三角形；
- 做题 3 题：10 分、0 分、10 分，平均分 6.67 分；
- 删除编号 103 后题目数量变为 2，平均分 10.00 分；
- 程序结束时按对象构造的逆序析构：main 中的 `t5(105)`、`t4(104)`、`t3(103)` 先撤销 → 题库《三角形判断题库》输出析构信息、其内部 2 道题目（104、101）随之撤销 → 《未命名题库》及其空数组 → 最后 `t2(102)`、`t1(101)`。可见题库内部的题目对象**不需要手动释放**，由题库对象的析构过程自动带动，即组合关系下"整体撤销带动部分撤销"。
